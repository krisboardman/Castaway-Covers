# Product Science

This document captures the domain knowledge that makes Castaway Covers work — how furniture dimensions become fabric covers. Any session modifying calculators, pricing, or product configuration must read this first.

Formulas documented from source code as of 2026-03-13. Not yet validated against Kris's production experience.

---

## Six product types, three calculation models

| Product Type | URL Slug | Shopify SKU Prefix | Calc Model | Field Count |
|---|---|---|---|---|
| Chairs & Recliners | `chairs-recliners` | `chairs/recliners` | Model 1 (backrest) | 6 (backWidth optional) |
| Sofas & Loveseats | `sofas-loveseats` | `sofas-loveseats` | Model 1 (backrest, 2-lane) | 5 |
| Chaise Lounge | `chaise-lounge` | `Chaiselounges` | Model 2 (chaise) | 5 (armLength optional) |
| Ottomans | `ottomans` | `Ottomans` | Model 3 (rectangular) | 3 |
| Tables | `tables` | `tables` | Model 3 (rectangular) | 3 |
| Table Sets | `table-sets` | `tablesets` | Model 3 (rectangular) | 3 |

**SKU casing is inconsistent.** `chairs/recliners` uses a slash and lowercase. `Chaiselounges`, `Ottomans` are capitalized. `sofas-loveseats`, `tables`, `tablesets` are lowercase. This matters for Shopify variant lookup.

**Sofa label inversion.** The `sofas-loveseats` config maps the internal field `width` to the UI label "Length" and the field `length` to "Depth". The internal variable named `width` holds what the customer calls the length of the sofa. This is inverted from every other product type.

**Chaise "Height" meaning.** The chaise lounge `height` field is labeled "Floor to Bottom of Seat" — it is NOT the overall height of the piece. `armrestHeight` is labeled "Floor to Top of Armrest". Both are floor-to-point measurements, not dimensions of the furniture itself.

## Model 1: Seated furniture with backrests (chairs, sofas)

All inputs are in inches. `length` = Depth (horizontal floor projection from back to front edge). `height` = overall height. `armrestHeight` = floor to top of armrest. `backrestDepth` = depth of backrest.

### AT2F (Armrest-Top to Front diagonal)

```
AT2F = √[(height - armrestHeight)² + length²]
```

The vertical component is `height - armrestHeight`. The horizontal component is `length` (depth). This is the hypotenuse of the triangle formed by the seat back above the armrest and the seat depth.

### Main Length (ML)

```
ML = (height + backrestDepth + AT2F + armrestHeight) - (2 × FC)
```

### Additional Length (addLength)

```
addLength = armrestHeight + AT2F + backrestDepth - FC + hem
```

### Per-lane length

```
perLaneLength = ML + addLength
```

### Chairs (FC=6", hem=0.5", 1 lane)

```
yards = ceil(perLaneLength / 36)
```

### Sofas (FC=4", hem=0.5", 2 lanes)

```
yardsPerLane = perLaneLength / 36
totalYards = ceil(yardsPerLane × 2)
```

The `ceil` is applied **after** multiplying by 2. This avoids over-rounding that would occur if each lane were ceiled separately.

## Model 2: Chaise lounges

Inputs: `width` (arm to arm), `length` (folded down), `height` (floor to bottom of seat = FTBS), `armrestHeight` (floor to top of armrest = FTA). `armLength` is collected but not used in the yard calculation.

Constants: FC = 3", BOLT_WIDTH = 54".

```
mainLength = length + 2 × (FTBS - 3)
mainWidth  = width  + 2 × (FTA  - 3)
```

If `mainWidth > 54`:
```
additionalLength = (mainWidth - 54) + 2
```
Otherwise `additionalLength = 0`.

```
totalLength = mainLength + additionalLength
yards = ceil(totalLength / 36)
```

The bolt width constraint adds extra length when the piece is wider than the 54" material bolt. The `+2` is an undocumented seam/overlap allowance.

## Model 3: Simple rectangular (tables, table sets, ottomans)

Inputs: `width`, `length`, `height`. All three product types use identical logic.

Constants: FC = 4".

```
drop = max(0, height - FC)
ML   = max(0, length + 2 × drop)
yards = ceil(ML / 36)
```

`drop` is the amount the cover hangs down each side (height minus floor clearance). `ML` is the total length of fabric needed to cover the top and both long drops. `width` is collected but **not used** in the yard calculation — it determines cut width on the production side, not yards ordered.

**Note:** Model 3 does not check whether `width + 2×drop` exceeds the 54" bolt width. Wide rectangular pieces may require a seam that the calculator does not account for.

## Two SKU systems

### Display SKU (internal, shown to customer)

Generated by `calculateSKU()`:

```
{PRODUCT_TYPE_UPPERCASE_3_CHARS}-{length}x{width}x{height}
```

Example: `SOF-72x36x34`

The prefix is `productType.toUpperCase().slice(0, 3)`. There is a dead code path for `productType === 'chair'` (singular) that would append backHeight — this path is never reached because the slug is `chairs-recliners`.

### Shopify SKU (used for variant lookup)

Generated by `generateShopifySKU(yards)`:

```
{shopifyProductType}-{yards}
```

Examples: `chairs/recliners-3`, `sofas-loveseats-5`, `Chaiselounges-4`, `Ottomans-2`, `tables-3`, `tablesets-4`

The `shopifyProductType` comes from a hardcoded mapping object. The yard count is the sole differentiator between variants of the same product.

## Variant lookup chain

When the customer clicks Calculate, the code performs a 5-step lookup:

1. Call `findVariantBySKU(shopifySKU)` — direct SKU match against Shopify.
2. If not found, fetch all products (up to 250) via the Storefront API.
3. For each product, check if handle or title contains the product type string.
4. For each matched product, check if any variant title equals `"{yards} yards"` or `"{yards} Yards"` (case-insensitive fallback included).
5. If still not found: **HARD FAILURE** — fires `alert("Product variant not found for {yards} yards. Please contact support.")`, sets `variantId` to empty string `''`, and calls `onCalculate` with the locally-computed `price` and disabled cart functionality.

There is no graceful fallback that lets the customer proceed to checkout. An empty `variantId` means the Add to Cart button will be non-functional.

## Total order price formula

```
basePrice     = yards × $45
premiumUpcharge = isPremium ? yards × $4 : 0
snapStraps    = snapStraps ? $20 : 0
handles       = handles ? $20 : 0
splitCover    = magnets ? $35 : 0

total = basePrice + premiumUpcharge + snapStraps + handles + splitCover
```

The `$45/yard` base rate is hardcoded in `calculatePrice()` in `MeasurementCalculator.tsx`. When a Shopify variant is found, the actual Shopify price overrides this local calculation: `finalPrice = parseFloat(variantInfo.price) || price`. If Shopify returns a price of `0` or unparseable, it falls back to the locally-computed value.

## Gusset fabric

The profit calculator (`calculators/profit_calculator.html`) includes separate fields for gusset fabric: yards needed (default 0) and price per yard (default $6.00). Gusset fabric is a separate, typically lighter-weight material used for structured panels or insets on some cover designs.

The relationship between a customer's order and whether gusset fabric is required is not documented or computed anywhere in the ordering flow. The profit calculator treats it as a manual input. It is assumed Kris determines gusset requirements from the order details.

## Known issues

**AT2F error compounding.** `calculateAngle()` uses `measurements.length` as the horizontal component (depth), which is correct. However, AT2F appears twice in `ML` and once in `addLength`, meaning any measurement error in depth or armrest height compounds through three terms.

**Depth confusion.** The field named `length` holds what customers understand as "depth" (the horizontal floor projection). The label says "Depth" but the internal variable is `length`. In the sofa config, `width` is labeled "Length" by the customer-facing UI. The naming is reversed from intuitive expectation.

**Sofa label inversion.** The `sofas-loveseats` productConfig maps field `width` → UI label "Length" and field `length` → UI label "Depth". Code references to `measurements.width` for sofas are the sofa's linear length, not its width.

**SKU casing inconsistency.** The Shopify SKU prefix mapping uses inconsistent casing: `chairs/recliners` (lowercase + slash), `sofas-loveseats` (lowercase), `Chaiselounges` (capitalized, singular despite URL slug `chaise-lounge`), `Ottomans` (capitalized), `tables` (lowercase), `tablesets` (lowercase, no hyphen). Any script or lookup that normalizes case will break some lookups.

**$45 fallback price.** If Shopify variant lookup fails entirely, the local `calculatePrice(yards)` at $45/yard is passed to `onCalculate` but `variantId` is `''`. The customer sees a price but cannot add to cart. There is no mechanism to surface the $45 fallback as a functional cart item.

**Optional fields not excluded from AT2F guard.** `backWidth` (chairs) and `armLength` (chaise) are explicitly excluded from the required-fields check before calculating. However, `armLength` is collected for chaise but is not used anywhere in `calculateYards`. Its purpose is undocumented.

**Floor clearance rationale undocumented.** Chairs use FC=6", all other types use FC=3" (chaise) or FC=4" (sofas, ottomans, tables, table-sets). No comment in the source explains why chairs have a larger floor clearance.

**Rectangular bolt width not checked.** Model 3 (tables, ottomans, table-sets) does not check if `width + 2×drop` exceeds the 54" bolt width. Wide rectangular pieces will be under-quoted on yards if they require a seam.

**`magnets` variable name.** The state, props, and callback for "Split Cover with Snaps" are all named `magnets` (`onMagnetsChange`, `initialMagnets`). The feature description says "marine-grade snaps", not magnets. Renaming would require coordinated changes across `AddOnOptions.tsx`, `cart/page.tsx`, and `store/`.
